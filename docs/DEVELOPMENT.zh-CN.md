# DSH 协作导航

让 DeepSeek Harness 与用户共同理解项目，主动补齐知识与资料，形成推荐并推进实际成果。对陌生或复杂项目，先介绍全貌与相关成果，了解相关背景、项目理解和具体知识缺口，再边介绍、边提问、边做。目标明确时直接完成。

插件明确要求优先完成用户的目标。列表、版本、分阶段开发和最小可行实验按实际收益使用；不把这些方法变成默认流程，也不把完整任务擅自缩小成演示原型。

## 安装与使用

使用 DSH 0.2.2 预发布版；服务集成测试已验证 0.2.2-rc.1 和 0.2.2-rc.3。包内直接提供可执行的 JavaScript，不需要运行构建脚本。GitHub 仓库：https://github.com/X-Roman-666/dsh-collaborator 。当前提供本地安装包，未发布到 npm 注册表。

桌面端可直接从侧栏“插件 → 添加插件”安装：在输入框粘贴本地 `.tgz` 文件的绝对路径，点击“安装”并启用。已安装旧版时，先在“已安装插件”中卸载旧版，再添加新版。安装后按下文确认实际加载版本。测试资料检索时，还需启用宿主的网页搜索与获取能力。

在插件所在目录中，向你实际使用的配置安装当前目录：

```powershell
dsh plugin --profile desktop add .
```

也可以安装提供的本地包：

```powershell
dsh plugin --profile desktop add ./dsh-collaborator-0.1.5.tgz --ignore-scripts
```

使用 Web 配置时把 `desktop` 换成 `web`。若 `dsh` 未加入 PATH，使用桌面应用提供的命令行入口或其插件安装功能。重新打开会话后直接描述任务即可；日常简单问答不会被要求完成入门问卷。

支持 `/collaborate 任务描述` 开始任务、`/collaborate off` 暂停、`/collaborate on` 恢复、`/collaborate status` 查看记录。命令依赖宿主的 commands 服务；没有该服务时仍能在对话中使用 collaboration 工具。

卸载：

```powershell
dsh plugin --profile desktop remove dsh-collaborator
```

## 能力与数据

插件把协作规则添加到系统提示中，提供一个 collaboration 工具，用于保存目标、约束、按主题观察到的知识缺口、决定依据、资料和进展。记录写入当前 DSH 会话的插件事件，并随宿主会话持久化和恢复；不同会话各自独立。新建其他会话不会自动共享项目记忆。

插件在宿主工具说明之后另加一段简短的当前回复指导，明确区分开放意图与具体任务：关键用途未知时把问题前置，具体任务直接做，明确要求总览时正常给总览。它不做关键词路由、不强行截断回复，也不额外调用评审模型。`/collaborate status` 显示实际加载的插件版本，便于确认更新。

持续协作监测从公开的会话事件中识别“提问返回后尚未解释”和“连续工具工作却没有可见说明”。在后续模型请求的动态上下文中给出沟通提醒，不读取内部推理、不强制提问、不阻止工具，也不额外消耗一次评审模型请求。长时间运行的单次工具只能在下一个模型生成时机得到提醒。提醒的传递可由程序验证，模型是否给出有用说明仍需真实对话试用。

0.1.3 增加共同理解引导：区分用户的相关经验、对项目的理解和具体主题的知识缺口；技术参数不代表用户已理解项目。探索性任务主动检索论文、开源项目、公司或产品、高校与科研团队、论坛或社区中的相关成果，给出链接、借鉴点及适用条件；不用无关资料凑类别。已有目标足以查阅代表性成果时，不要求用户先确定所有用途。相关背景、项目理解、已介绍的领域图景和分类资料随会话保存；旧版记录自动兼容，未知背景留空。记录缺失只是提醒，不会阻止执行明确任务。

0.1.4 进一步区分“已介绍”“已提供资料”和“用户理解”：首次实质回复帮助用户看懂领域、组成关系与已有成果，自然了解起点和困惑；问题不要求用户先掌握术语。领域介绍和参考资料记录完整后，尚需解释或理解程度未知的主题仍会产生动态提醒；提醒根据用户反馈更新，未知不等于不会，也不要求逐项测评。旧版会话数据结构不变。

0.1.5 修正 DSH peer 版本范围，允许 0.2.2-rc.3 使用当前运行时提供的服务，而不是把依赖固定在 rc.1；协作规则与 0.1.4 相同。两版运行时的 20 项服务集成与交互状态测试均通过。

更新后需要让 DSH 重新加载插件；安装列表中的版本不代表当前进程已使用该版本。通过“应用 → 退出”完整退出后重新打开，在新会话输入 `/collaborate status`，确认显示 `0.1.5`、“持续协作监测：已启用”和“共同理解引导：已启用”。仅关闭窗口可能保留旧进程。

检索、文件处理和实际操作使用宿主已启用的工具。插件本身不发起额外模型或网络请求，不收集密钥、不发送遥测、不改动原有权限或替换其他系统提示。规则由宿主模型执行，实际协作效果需要在所选模型上结合真实任务评估。

## 开发与检查

标准开发环境运行 `npm install`、`npm run check`、`npm test`。测试使用真实的 DSH 服务检查加载、参数校验、任务隔离、恢复、暂停和卸载。项目不需要构建步骤；`npm pack` 可生成安装包。对话行为验收见 examples/acceptance.md。

实现入口在 src/index.js，任务记录与验证在 src/state.js，协作规则在 prompts/collaborator.md。修改规则后重新加载插件生效。

# 对话验收案例

在同一模型、同一工具配置下，用普通会话和启用插件的会话分别完成任务。比较成果是否可用、用户补充和纠正的负担，以及是否发现影响路线的重要遗漏。下面是验收依据，不是固定回复模板；不把模型说过某句口号当成通过。

| 用户输入或情境 | 应有行为 | 失败表现 |
| --- | --- | --- |
| 实际失败案例：“我如果想做一个类似于 Meshy、Tripo、Hyper3D 那样的网站应该怎么做？”用途、主要功能与交付尚未说明。 | 先介绍网站、生成服务与资产处理的关系，主动查阅相关的产品、开源或研究成果并说明借鉴点；自然了解用户的相关经验、对项目的理解和用途，再随回答继续介绍与收敛。 | 先给完整商业化报告并默认经营路线；或者只问预算和技术栈，问完就独自开始开发。 |
| “先不用问我，给我做一个这类网站的完整技术总览和路线比较。” | 直接提供所要求的总览与比较，有依据地说明适用条件。 | 机械地强制先回答问卷。 |
| “把这个 CSV 中各部门的总支出算出来，给我结果。”已提供完整文件。 | 直接读取、计算并交付；只在字段确有歧义时询问。 | 先安排多个版本、最小可行实验或能力测评。 |
| “我想把手里的特殊纸做成三维材质，完全不懂怎么弄。” | 解释影响路线的关键区别，询问用途和采集条件，随后推荐并开展可做的工作。 | 直接要求用户选择不理解的专业方案，或强制先学完整课程。 |
| 用户已提供服务器配置、代码和目标。 | 阅读材料，复用已知条件；检查更直接的已有工具。 | 再问一遍配置，默认自研、训练或搭建复杂系统。 |
| 用户说“这些问题我不知道，你先替我判断”。 | 给出有依据的默认建议，推进不依赖用户回答的工作。 | 循环提问或虚构用户偏好。 |
| 用户说“请按三个版本规划，并设计最小可行性实验”。 | 按明确要求规划，解释各实验如何减少不确定性。 | 因反流程规则拒绝用户需要的结构化方案。 |
| 一个简单处理能解决全部问题。 | 直接完成并做必要检查。 | 人为降格为样例、阶段一或演示原型。 |
| 存在投入很大的两种路径，缺失信息将改变路线。 | 提一个会改变决定的关键问题，同时处理独立工作。 | 为求速度擅自决定用途、预算或不可逆事项。 |
| 检索到相邻领域的已有方法。 | 说明迁移关系、适用条件、可复用内容和来源。 | 只给链接清单，或把论坛经验当成已证实结论。 |
| 暂停协作导航，随后恢复原会话。 | 暂停期间不注入导航指导；恢复后读到原任务进度。 | 不同会话串用记录、重复询问，或失去任务状态。 |
| 用户提出手机控制开关，回答“ESP32，通过 WiFi 控制”后，仍未确定触发条件、具体负载和使用环境。 | 先说明该回答确定了什么，介绍下一项关键区别并继续询问；推进已有依据的独立工作时及时介绍发现。 | 把一次回答视为完整需求，默默扩成多协议、配网、固件、网页与完整文档。 |
| 模型已经向用户提问，随后又连续执行多个工具步骤。 | 根据新发现持续介绍和澄清，不要求每步批准；无关键未知时说明进展并继续完成。 | 开场问完后始终无可见文字；或者为凑互动机械地反复提问。 |
| 用户回答“会 Python，也听说过 TRELLIS，但没做过这类网站”。 | 区分编程经验与三维生成项目理解，解释已有生成能力如何接入网站；提供核验过的相关成果，继续了解用户尚不清楚的部分。 | 把一个术语当成熟练证据，直接确定架构、计费、队列和部署。 |
| 用户说“先给我讲讲这个领域有哪些论文、项目、公司、科研团队和社区可以参考，我还不清楚要做成什么”。 | 先按当前领域检索并介绍代表性成果，说明各自与任务的关系和可借鉴内容，再根据反馈深入。 | 要求先确定全部用途才肯检索，或只交付一个没有解释的链接清单。 |
| 用户纠正“我对网页开发熟悉，主要不懂模型生成和后处理”。 | 更新背景和知识缺口，集中介绍模型与资产处理，不重复网页基础。 | 继续按整体新手教学，或因资料已介绍过而不再解释新的疑问。 |
| 用户只回答了开关设备和连接方式，没有说明是否做过嵌入式项目。 | 说明已确定的连接条件，介绍整个控制链路和可复用方案；结合回答自然了解相关经验，再决定讲解与实施深度。 | 把“ESP32＋WiFi”当成懂整个项目的证明，立即生成全套系统。 |
| 已介绍论文、开源项目和产品，用户只回复“继续”，随后问“生成模型是在网页里运行吗？” | 延续资料之间的关系解释，回应网页与生成服务的具体困惑；根据这条反馈更新该主题的理解观察，继续推进可独立完成的工作。 | 因资料已经介绍过便认为用户已掌握，直接输出全套开发代码，或要求用户复述来通过测评。 |
| 用户熟悉网页，但对模型后处理的经验尚未知；之后提供了后处理结果，再补充不理解某次失败。 | 按主题和最新反馈调整讲解，未知保持未知；能应用的部分不重复教学，新出现的具体困惑继续解释。 | 把熟悉网页推广为理解全部领域，或把“已掌握”永久固定，忽略后续纠正。 |

实际失败案例已确认系统提示中包含协作规则，模型可见 collaboration、web_search 和 web_fetch；该轮发生了 16 次检索或网页抓取工具调用。安装成功不等同于行为达到目标。更新后的程序测试检查指导注入和生命周期；同一真实问题的模型复测仍需在 DSH 中完成。

后续开关案例中，磁盘安装版本已更新，但该轮捕获的系统提示仍为旧内容；开场后连续七个模型步骤没有可见文字。此案例用于验证运行时的沟通信号及加载版本核对，不据此宣称尚未实际加载的新规则已经通过或失败。
